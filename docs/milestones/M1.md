# Milestone M1 — Retrieval Foundation

**Status:** Complete  
**Completion Tag:** `v0.4.0-m1-complete`

---

## 1. Purpose

Milestone M1 establishes the reliable retrieval foundation of the Knowledge Assistant.

M1 transforms source documents into structured, searchable evidence while preserving provenance and workspace isolation.

M1 deliberately ends at **ranked retrieval**.

LLM integration, context construction and answer generation are owned by M2.

This boundary is defined by:

- `docs/decisions/002-m1-retrieval-boundary.md`
    

---

## 2. Milestone Outcome

At completion of M1 the Knowledge Assistant can:

- discover documents belonging to a workspace;
    
- ingest supported document formats;
    
- extract and normalise document content;
    
- divide documents into semantically useful chunks;
    
- generate local embeddings;
    
- persist portable embedding artefacts;
    
- maintain a Chroma vector index;
    
- perform semantic similarity search;
    
- preserve source provenance throughout the pipeline;
    
- filter retrieval using metadata;
    
- evaluate retrieval using benchmark questions;
    
- expose the pipeline through the command-line interface.
    

M1 does **not** generate natural-language answers.

---

## 3. Processing Pipeline

```
Source Documents
       │
       ▼
   Discovery
       │
       ▼
   Ingestion
       │
       ▼
    Chunking
       │
       ▼
Embedding Generation
       │
       ▼
Portable Embedding Artefacts
       │
       ▼
   Vector Index
       │
       ▼
Similarity Retrieval
       │
       ▼
Ranked Evidence
```

Ranked evidence forms the stable interface between M1 and M2.

## 7. Retrieval Evaluation

M1 provides an evaluation framework for measuring retrieval behaviour.

Supported or planned metrics include:

- Recall@K
    
- Mean Reciprocal Rank
    
- similarity statistics
    
- retrieval latency
    

Evaluation is performed against explicit benchmark datasets rather than treating similarity scores alone as evidence of retrieval quality.

---

## 8. Provenance

Every retrieved chunk retains sufficient information to trace it to its originating evidence.

This includes, where available:

- workspace;
    
- document identifier;
    
- chunk identifier;
    
- source filename;
    
- relative source path;
    
- document title;
    
- section title;
    
- checksum;
    
- source metadata.
    

This provenance becomes the basis for citations in M2.

---

## 9. Workspace Isolation

All generated knowledge artefacts are workspace-scoped.

Typical layout:

```
workspaces/
    <workspace>/
        artifacts/
            ingestion/
            chunks/
            embeddings/
            chroma/
```

Source documents may reside outside the project repository.

Generated artefacts and source knowledge collections are not required to be committed to Git.

## 10. Command-Line Capability at M1 Completion

The relevant M1 commands are:

```
knowledge-assistant version
knowledge-assistant doctor
knowledge-assistant ingest
knowledge-assistant chunk
knowledge-assistant embed
knowledge-assistant index
knowledge-assistant search
knowledge-assistant evaluate
knowledge-assistant workspace
knowledge-assistant config

```

Question answering is intentionally absent from M1.

There is therefore no M1 requirement for:

```
knowledge-assistant ask
```

---

## 11. M1 Acceptance Criteria

M1 is complete when:

- documents can be ingested from a configured workspace;
    
- ingested documents can be transformed into retrieval chunks;
    
- embeddings can be generated locally;
    
- embeddings can be cached independently of the vector database;
    
- a persistent vector index can be created and maintained;
    
- natural-language queries can retrieve ranked chunks;
    
- retrieved chunks preserve provenance;
    
- retrieval can be objectively evaluated;
    
- workspace boundaries are respected;
    
- automated tests pass;
    
- the resulting retrieval interface is sufficiently stable for M2.
    

---

## 12. Explicitly Deferred to M2

M1 does not include:

- LLM invocation for answering questions;
    
- construction of LLM context from retrieved evidence;
    
- grounded natural-language answers;
    
- source citation presentation;
    
- answer confidence or uncertainty handling;
    
- unanswerable-question handling;
    
- conversational question answering.
    

These are M2 responsibilities.

---

## 13. Handoff to M2

The contract between M1 and M2 is:

> Given a question and retrieval parameters, M1 returns ranked, provenance-bearing evidence suitable for downstream reasoning.

M2 shall consume this interface rather than duplicate or bypass the retrieval subsystem.

This separation allows retrieval and generation to be evaluated independently.

---

## 14. Completion

Milestone M1 is complete.

The repository records the clean M1 handoff with:

```
v0.4.0-m1-complete
```

Further retrieval improvements may occur during later milestones, but they do not reopen M1.
